# 007 · 流水线派发 + 验收模式

## 这一版解决什么

把「待办」tab 从"两栏清单"改成**三个区**：流水线（左）· 今日仓库（中）· 长期仓库（右），
并验证一个产品判断：**验收不是一个 tab，是一个全屏模式**。

## 设计立场

**仓库是存储，流水线是执行。** 边界一旦划清，状态机只属于流水线；仓库里的卡没有状态、
没有进度、没有 assignee —— 只有标题和一句验收。

## 关键选择

- **布局**：三列，流水线最左（`302px` 固定），两仓库等分剩余宽度。流水线面板底色用 `--col`
  （凹槽感），仓库用 `--card`（平面感）—— 视觉分区即语义分区。
- **仓库卡片刻意"轻"**：无边框、无状态点、无进度条，hover 才浮出背景与「派发」按钮。
  一旦仓库里长出状态点，人就会开始管理仓库，它会长成第二个看板。
- **验收 = 全屏模式**：入口是右上角「待你处理 N」和流水线里的「待收」行。一张一屏，
  左样张 / 右验收标准 + AI 自述三行（交付·依据·没底），键位 `A 收` `R 不收` `S 跳过` `Esc 退出`。
- **R 不收强制写理由**：不写则「确认不收」禁用。理由是唯一天然会变成规则/skill patch 的输入。
- **派发闸门**：验收栏为空的卡拖进流水线会被**拦下并抖动**，提示先补「怎样算做完」。
- **派发回执**：入队后立即显示"第 N 位 · 预计 HH:MM 开始"，避免重复点击。

## 试这些

| 动作 | 预期 |
|---|---|
| 拖最上面那张「调研 Tailscale…」到左列 | 入队，提示第 3 位 · 预计 14:19 开始 |
| 拖「给工作台加详情抽屉」（验收未写）到左列 | 被拦下 + 抖动 + 红色提示 |
| 点「待你处理 3」或流水线里的待收行 | 进全屏验收模式 |
| 按 `A` | 收入「已完成」，下一张顶上，进度 2/3 |
| 按 `R` | 弹出必填理由框，不写不能确认 |
| 按 `S` | 跳过，本张排到队尾 |
| 右上角 ☾ / ☀ | 明暗切换（全部颜色走 token） |
| 底部输入框回车 | 建卡落今日仓库，验收栏为空并标黄 |

URL 参数（便于截图/评审）：`?theme=dark`、`?review=1`、`?why=1`、`?tab=flow|done`。

## 取舍

- **强在**：派发这件事的"承诺感"很明确（拖进去才算数），验收路径短、有终点、有完成感。
- **弱在**：三列在 1320px 下每列偏窄；仓库空了会显得空荡；验收是模式，第一次用需要知道入口在右上角。
- **未做**：真正的样张翻页、验收后自动生成规则、卡片的键盘全流程（j/k）。

## 适合

一天派 3–10 张卡、产出物是 PPT/报告/表格这类"大件"的个人工作台。
不适合高频小任务（那才需要攒批和抽样验收）。
