## Variant: Plan + Flow（005，当前定稿方向）

### Design stance
把「安排」和「执行流程」拆成两个正交视图：
- **待办 tab**：人的工作台。左「待办仓库」（长期池）右「今日待办」（今天要做），都是列表，互相拖拽分配。
- **看板 tab**：AI 的流程视图。六列状态（待整理→待执行→就绪→运行中→待拍板→待验收），拖卡片 = 改状态。

### Key choices
- Layout：Calm Linear 排版骨架（侧栏 + 居中面板 + 发丝线），看板复用 Ops Cockpit 的紧凑六列
- Theme：CSS 变量双主题，右上角切换，localStorage 记忆，跟随系统初始值
- Drag & Drop：
  - 仓库 ↔ 今日：左右互拖（含插入位置，行上下半区判定）
  - 今日/仓库内部：拖动重排
  - 看板：卡片跨列拖动 = 改 status
- New task：侧栏 + 顶栏两个「＋ 新建待办」按钮；弹窗含标题/类型/项目/优先级/备注/「同时加入今日待办」/「AI 补全任务书」
- 快速录入：今日栏顶部输入框 + 回车

### Trade-offs
- Strong at：人机分工清晰——人只管"今天做哪些"，AI 状态不打扰；仓库和今日互换零成本
- Weak at：看板与待办是两个 tab，跨 tab 看全局需要切换；移动端双栏会挤成单栏（需响应式）

### Best for
本项目的目标形态：Hermes 管家跑流程，人只做「今天做什么」的编排 + 拍板。
