## 1. 核心模型（三句话）

1. **卡 = 契约**：卡上只写两栏——**输入**（用哪些材料/仓库/分支）与**验收**（怎样算对，一句话、可判定）。
   预算与禁区不写在卡上，走三层默认：全局 → `routing.json` 的路线包 → 卡覆盖；**`ready` 那一刻把生效值快照进 `task.metadata`**，事后可审计。
2. **仓库存信息，流水线产状态**：仓库卡只有标题 + 验收，**没有状态点、没有进度、没有 assignee**；
   进流水线才有 `ready → running → review → done`。仓库卡统一 `triage`，今日/长期用 `metadata.bucket` 区分，不占 `todo`。
3. **完成即固化**：进 `done` 的前提是抽出至少一件可复用件——一条 `routing.json` 规则 / 一次 skill patch / 一个可重跑脚本。
   固化物有 `未验证 → 已验证` 两态，**被下次任务真正引用过才转正**；KPI 看"已验证沉淀数"，不看"完成卡数"。

状态映射（零内核改动）：

| 工作台概念 | kanban 状态 | 判定 |
|---|---|---|
| 今日 / 长期仓库 | `triage`（`metadata.bucket=today\|long`） | 拖进流水线前 |
| 流水线·队列 | `ready` | 契约齐全、等 worker 认领 |
| 流水线·运行 | `running` | dispatcher 已 claim |
| 流水线·待收 | `review` | worker 干完，等人判断 |
| 已收 | `done` | 人按 A，且固化物已登记 |
| 退回 | 回到 `triage` | 人按 R，卡带一句退回理由 |

## 2. 界面结构：两个自有视图 + 一个复用 + 一个排障

```
待办（默认落地，自有）
├─ 流水线（最左，凹槽底色）   队列 / 运行中（管道位置=进度）/ 待收
├─ 今日待办（中）             轻卡片：标题 + 验收一行
├─ 长期待办（右）             同上，冷存储
└─ 底部一句话建卡             默认落今日；回车后不自动派发

验收（全屏模式，自有）        入口：右上角「待你处理 N」/ 流水线「待收」
├─ 左：产出物样张（PPT 页/报告/表格，可翻页）
├─ 右：验收标准原文 + AI 自述三行（交付/依据/没底）+ 本次运行（worker/耗时/花费）
└─ 底：A 收 · R 不收（必填理由）· S 跳过 · Esc 退出；清空即退出

看板（复用 Hermes 原生）      8 列、原生卡片、拖拽换列=改状态。不自建、不重画。

运行画布（排障页，非默认）    拓扑 + 流动 + 账；只在"起疑"时打开，5s 刷新即可
```

## 3. 范围（MoSCoW）

### Must · v0.6 的第一批

| # | 事项 | 关键实现 | 预估 |
|---|---|---|---|
| M1 | 卡契约 + 派发闸门 | 验收为空 → 拖进流水线被拒并提示，不允许进 `ready` | 0.5 天 |
| M2 | 待办三区重排 | 流水线左/今日/长期；HTML5 拖拽；**派发回执**（第 N 位 · 预计 HH:MM） | 1 天 |
| M3 | 验收全屏模式 | `A/R/S/Esc`；R 必填理由；收完写 `done`，退回回 `triage` | 1 天 |
| M4 | 通知 P0 | 右上角计数 + 系统通知；手机只接 P0（ntfy / Bark 二选一） | 0.5 天 |
| M5 | 看板回归原生 | 删除自建 5 列，改嵌 Hermes kanban 视图 | 0.5 天 |

### Should · 第二批

| # | 事项 | 说明 |
|---|---|---|
| S1 | AI 自述三行 | worker 约定改 `kanban_complete` 的 summary 结构；验收页渲染「没底」用警示色 |
| S2 | 运行画布 v1 | 拓扑 + 管道位置表达进度；今天泳道；累计热力图放 v2 |
| S3 | 完成即固化 v1 | 验收页加"这件东西下次能怎么用"三选一；落 `~/Projects/Jarvis/routing.json` 或 skill patch |
| S4 | 验收槽 | 固定容量 3，有空槽就推、没空槽排队；同批 `decompose` 的子卡自动成束 |

### Could · 有余力再说

- 验收三档分流（机器验 / 抽样验 / 前置审批）——当前任务量还用不上抽样
- `POST /ingest` 自动提取（邮件/私信 → 候选，带原文锚点，不直接建卡）
- 累计热力图（哪条路径走过 20 次 → 下一步该固化什么）
- 三层默认的审计面板（改了默认，历史卡片的快照不受影响）

### Won't · 本版明确不做

自建看板 · 改上游内核"续原会话" · 跨主机 kanban / ECS 执行节点 · 只留一个 worker（无证据） · 谎报降权 · QQ 接入

## 4. 依赖顺序

```
M5 ──→ M2        先删掉自建的 5 列，三区重排才不会两套并存
M1 ──→ M2        闸门决定拖拽行为
M3 ──→ M4        先有验收模式，通知才有落点
M3 ──→ S3        固化在验收那一刻触发
M2 ──→ S2        画布读同一份状态
```

三步走：

1. **第 1 周**：M5 → M1 → M2（界面骨架 + 派发闸门，能真派活）
2. **第 2 周**：M3 → M4（闭环成立：派出去、跑完、推给你、你验收）
3. **第 3 周**：S1 → S3（系统开始自己变强：自述可反驳、完成即固化）

## 5. 验收标准（每条都可判定）

| # | 怎么算过 |
|---|---|
| M1 | 建一张验收为空的卡 → 拖进流水线被拒 + 提示 → 补完可派发 |
| M2 | 从今日拖一张到流水线 → 3 秒内出现"第 N 位 · 预计 HH:MM" |
| M3 | 点「待你处理 3」→ 全屏验收 → 按 A 后进已完成；按 R 不填理由不能提交 |
| M4 | 构造一张 P0（有子卡被堵）→ 10 秒内收到系统通知；非 P0 不打扰 |
| M5 | 看板 tab 显示原生 8 列，拖拽换列真的改状态 |
| S1 | 任一张卡的验收页能看到三行自述，「没底」不为空 |
| S3 | 一张卡完成后，`routing.json` 或 skill 目录里出现一条新条目，且标记"未验证" |

## 6. 需要你拍板的三个开放问题

1. **第 N 次成本怎么记**：先手工记一张 CSV（任务类型 / 第一次耗时 / 第二次耗时），还是直接从 `task_runs` + magpie `usage.jsonl` 聚合？
2. **手机通道**：ntfy（自建/公共实例，Android 最省事）还是 Bark（iOS）？还是先只做桌面，手机延到 v0.7？
3. **固化物的权限边界**：worker 能不能自己改 `~/.hermes/profiles/*/skills/`？还是只能提 patch、由你合？
